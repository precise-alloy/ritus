## Error handling

Domain errors extend `LedgerError` (`src/errors.js`) and carry a stable `code`. Library code throws; `main()` in
`src/cli.js` turns any error into `Error: <message>` and exit code 1.

## Testing

`node:test` with `node:assert/strict`. One test file per module in `test/`, named `<module>.test.js`. Anything that
touches the ledger uses `tempLedger()` from `test/helpers.js`. Expected values are written out as literals, never
computed with the production code.

Test locations:

- `src/<module>.js` -> `test/<module>.test.js`

## Module map

| Module            | Responsibility                                               |
|-------------------|--------------------------------------------------------------|
| `src/money.js`    | Integer-cent amounts: formatting (and parsing, when present) |
| `src/fees.js`     | Fee schedule and `computeFee()` for every fee kind           |
| `src/ledger.js`   | File-backed `Ledger`; the only code that reads or writes balances |

| `src/cli.js`      | The `tl` command                                             |

## Project-specific constraints

- Money is integer cents from input to output; no floats for amounts (D-001).
- Fees round half-up to the cent, for every fee kind (D-002).
- Every balance read and write goes through `Ledger` (D-003). `src/` uses async I/O only (lint rule `async-io`).
- Only `src/cli.js` prints to stdout (lint rule `no-console`).
